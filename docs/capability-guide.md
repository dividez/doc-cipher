# DocCipher 能力边界手册

本文说明 DocCipher **能做什么**、**不能做什么**，以及预览与命中预估的局限。便于用户与实施方建立合理预期。

## 产品定位

DocCipher 是**完全离线**的 Word `docx` 脱敏与还原桌面客户端：

- 选择 docx → 预览并确认敏感内容 → 脱敏 → 生成 `masked.docx` + `restore.enc`
- 使用 `restore.enc` 与还原密码在本地还原文档

**不是**：Word 编辑器、云协作平台、OCR 工具、大模型内容审核服务。

## 能做到

| 能力           | 说明                                                   |
| -------------- | ------------------------------------------------------ |
| 本地脱敏与还原 | 原文与映射文件不出本机；支持编辑后的 docx 部分还原     |
| 正则规则       | 手机号、身份证、邮箱等（可在设置中全局开关）           |
| 系统关键词     | 默认模板中的通用词表，受「系统关键词」开关控制         |
| 方案关键词     | 按业务场景保存的方案词表（`profile_keywords`）         |
| 手动划词       | 预览中划词采集文本为手动词，全文子串匹配脱敏           |
| 文档预览       | docx-preview 只读版式预览（原文或脱敏后文档）          |
| 命中预估       | 脱敏前统计规则命中，弹窗详情（预览内不高亮 v1）        |
| 还原报告       | 输出 `restore-report.json`，统计成功、缺失、未知 token |
| 方案管理       | 新建、保存、导入、导出、复制                           |
| 任务历史       | 本地索引最近脱敏/还原记录                              |

## 做不到（当前版本）

| 期望             | 说明                                             |
| ---------------- | ------------------------------------------------ |
| OCR / 扫描件     | 仅处理 docx 内已有文本，不识别图片或 PDF         |
| 语义理解 / LLM   | 不做「像敏感信息」的推理，仅正则、关键词与手动项 |
| 多人协作         | 无账号、无共享方案、无云端同步                   |
| 在线 Word        | 不替代 Microsoft Word/WPS 的编辑能力             |
| PDF / xlsx 等    | 仅支持 `.docx`                                   |
| 与 Word 完全一致 | docx-preview 版式预览，复杂域/嵌入对象可能偏差   |
| 表格单元格级编辑 | 预览标注表格区域，脱敏仍按段落文本处理           |

## 预览与命中预估的局限

1. **预览与脱敏解耦**：版式预览由 Renderer 的 docx-preview 负责；脱敏/还原由 Main OOXML 处理。预览加载失败不影响脱敏。
2. **命中扫描**：Main 从 OOXML 拼接段落文本做匹配，与 docx-preview DOM 无对应关系；预览内对**手动词、方案/系统关键词**在 DOM 连续文本上子串高亮（可覆盖跨样式拆分的词），与 OOXML 命中数量**不要求一致**；**正则等规则命中**见弹窗统计。
3. **非语义匹配**：关键词与手动词均为子串 `indexOf`，可能误命中或漏掉同义表述。
4. **命中预估不修改文件**：仅模拟匹配逻辑，与最终脱敏结果在边界情况下可能略有差异。
5. **手动词**：划词只采集选中文本，不记录段落位置；脱敏时在全文各段落内查找该词。
6. **预览内查找**：文档预览支持 `Ctrl+F` / `Cmd+F` 在当前版式 DOM 内搜索并跳转，与 OOXML 命中统计及脱敏逻辑无关。

## 重叠命中

多个关键词或手动词可能在同一段文字上**子串重叠**（例如「租赁期间」同时命中「租赁」与「赁期」）。脱敏流程为：

1. **先收集**段落内全部候选命中（`findMatches`）；
2. **再消解**重叠（`selectMatches`）：**最长优先**；长度相同则**更靠左**优先；每段字符最多替换为一个 token，不允许嵌套或双重覆盖；
3. **最后统一替换**为占位符（非边找边替换）。

示例：段落「租赁期间」同时配置「租赁」「赁期」时，仅脱敏「租赁」，结果为 `[MANUAL_…]期间`。命中预估与预览高亮均按消解后的结果计数/显示，同一段重叠区域不会显示两个 token。

## 系统关键词 vs 方案关键词

| 类型       | 规则 ID            | 配置位置                  | 生效条件                     |
| ---------- | ------------------ | ------------------------- | ---------------------------- |
| 系统关键词 | `keywords`         | 设置 → 默认规则模板       | 设置中「系统关键词」开关为开 |
| 方案关键词 | `profile_keywords` | 方案管理 / 脱敏页当前方案 | 随当前选用的脱敏方案         |

划词加入脱敏的内容属于**本次手动词**；保存方案时可将手动词文本并入**方案关键词**。

## 数据与隐私

- 脱敏映射保存在 `restore.enc`，使用用户设置的密码经 AES-256-GCM 加密。
- 还原密码和 `restore.enc` 格式严格校验；masked docx 的 SHA-256 不一致时不阻断，写入报告和日志。
- 还原只处理完整且精确匹配的 token；被用户删除、编辑或拆坏的 token 跳过，不做模糊猜测。
- `restore-report.json` 只记录 token 状态与次数，不记录原文。
- 应用日志与 `setting.json`、方案文件、任务索引均存储在用户本机数据目录。
